# CareTime → DTC app migration

Moves the active client roster and staff roster out of CareTime and into the DTC
app's Firestore, so the app can own forms, filing and compliance while CareTime
keeps scheduling, EVV and billing.

## What's here

| File | What it is |
|---|---|
| `caretime-clients.json` | 30 active clients, extracted 2026-08-03 |
| `caretime-staff.json` | 35 **active** staff (CareTime lists 70; half are inactive) |
| `import.mjs` | The importer — clients and staff are separate commands |
| `staff-plan.json` | Generated by `staff --dry-run`; review before creating accounts |

## Before you run it

You need a service-account key so the script can write to Firestore from a
terminal rather than the browser:

1. Firebase console → Project settings → Service accounts → **Generate new private key**
2. Save the JSON somewhere outside the repo (it is a credential — do not commit it)
3. `export GOOGLE_APPLICATION_CREDENTIALS=/path/to/serviceAccount.json`
4. `npm install firebase-admin` (in the repo root)

## Running it

Always dry-run first.

```bash
node migration/import.mjs clients --dry-run
node migration/import.mjs clients

node migration/import.mjs staff --dry-run   # writes staff-plan.json
# review staff-plan.json
node migration/import.mjs staff
```

Both commands are **idempotent** — clients are matched by name and staff by
email, so re-running updates existing records instead of creating duplicates.

## Re-extracting

The JSON files were scraped from CareTime's list views (Clients → Client List with
the *Active* filter; Caregivers with the *Active Caregivers* filter). If the
rosters change, re-extract rather than hand-editing, so the data stays traceable
to CareTime.
